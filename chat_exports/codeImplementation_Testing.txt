  What the sample notes showed

  The first run read only 2 of 36 files. The notes mostly use plain Date: and
  Attendees: header lines, not YAML, and the old parser rejected them. After the
  fixes below, I checked every stored item by hand against its note.

  Changes

  - Headers and dates: the parser accepts plain Date:/Attendees: header lines as
    well as YAML. It reads dates like 9 September 2026 and Monday, 14 September
    2026.
  - Bullets: * and + bullets and nested items now count as items.
  - Text that isn't an action:
    - Fenced code, HTML comments and > quotes are ignored.
    - Before, the code-fence example and the quoted Karan to refund… line would
      have been stored as real items.
  - Due dates: the resolver now handles:
    - Oct 3rd
    - Wed 16 Sep
    - Saturday 10 Oct
    - EOD and EOD tomorrow
    - end of next week
    - next Tuesday
    - mid-October
    - — by Friday
  - Skipping a non-date by: an earlier non-date such as by 10% no longer hides
    the real date, as in cut costs by 10% — proposal by 2026-10-09.
  - Owners:
    - @anita: … and Lena (with Priya) to … now resolve.
    - Everyone, Team, Someone and TBD are stored as unassigned without a
      warning.
  - Specs: I recorded these changes as amendments in the affected module specs.

  What it does on the real notes

  - Skipped: 5 notes, each reported with its reason:
    - the empty file
    - scratch.md, which isn't valid UTF-8
    - untitled.md, which has no header
    - the standup with no attendees
    - the sales note dated "sometime last week"
  - Merged: repeated items merge across meetings. A [x] in a later note marks
    the item done, and the latest due date is kept.
  - Ambiguous owners: 5 items are stored unassigned with an "ambiguous owner"
    warning, because both Priyas or both Rahuls attended.
  - Re-running ingest: adds, merges and updates nothing.
